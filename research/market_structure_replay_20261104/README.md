# EMBER / Market Structure Replay (R-MSR-01, 2026-11-04)

**Статус: RESEARCH_ONLY / CAUSAL_RECOGNITION_PROTOTYPE.** Это проверка корректности *распознавания* рыночных событий на локально скачанных свечах, **не торговая стратегия**, не торговый бот и не доказательство прибыли. Никаких сетевых запросов, API-ключей или ордеров. Исследовательская ветка; SMOKE/PAPER/автоматизации не меняются.

## Функции

- 15m UTC futures OHLCV считываются из локальных CSV. При пропуске, дубликате, неправильном порядке, смешении тикеров, неверном времени или недопустимом OHLC **весь ряд отклоняется**.
- Закрытые свечи **1H и 4H** агрегируются причинно из 15m; неполная старшая свеча не доступна распознавателю.
- Swing high/low подтверждается только спустя **2 правые 15m-свечи**; в событии сохраняется время, когда swing стал известен. Это согласовано с временным принципом `ember.core.features.FeatureBuilder`, но не означает полной совместимости с его классификатором BOS.
- Диапазон накопления **замораживается заранее** по 12 завершённым 1H-свечам; затем отдельно отслеживается выход за границу и возврат внутрь.
- Для каждого диапазона ведётся независимый кандидат со стадиями `WAIT_SWEEP` и `WAIT_STRUCTURE`; один кандидат не блокирует все остальные на монете. Перекрытия >80% подавляются для предотвращения клонирования одного диапазона.
- После sweep ищется пробой **ранее подтверждённого** pivot-уровня, отдельно фиксируется FVG после sweep. Проход BOS не означает доказанного разворота и не создаёт ордер.
- Журнал `events.jsonl` содержит time-known события: `PIVOT_*`, `ACCUMULATION_LOCKED`, `SWEEP_RETURN`, `FVG_AFTER_SWEEP`, `STRUCTURE_BREAK_CONFIRMED`, `EXPIRED_*`, `REJECT_*`.
- Необязательный `future_outcomes_POSTHOC.csv` создаётся только после завершения распознавания; в распознающий код не передаётся. Это характеристики исхода (MFE/MAE по завершённым будущим барам), **не PnL**.
- `compare_annotations.py` сравнивает события с независимо размеченными временными метками; без аннотаций не объявляет ни accuracy, ни «правильность чтения рынка».

## Входные данные

Формат одного файла на инструмент:

```csv
symbol,time,open,high,low,close,volume
BTCUSDT,1788220800000,123.4,123.8,122.8,123.2,140
```

`time` — **UTC open**, миллисекунды Unix или ISO-8601 с явным часовым поясом. Запись **только закрытой** 15m-свечи, а время появления признака — `time + 15m`. Для Binance Vision берём ТОЛЬКО `data/futures/um/*/klines/{SYMBOL}/15m/` (не Spot и не COIN-M). Публикуем `.CHECKSUM` и SHA256 ZIP/нормализованного CSV, оговаривая, что checksum с того же сервера не является независимой цифровой подписью.

Скачанные **локально** ZIP и `.CHECKSUM` лежат в одной папке, например:

```text
BTCUSDT-15m-2026-08.zip
BTCUSDT-15m-2026-08.zip.CHECKSUM
BTCUSDT-15m-2026-09.zip
BTCUSDT-15m-2026-09.zip.CHECKSUM
```

Запуск из директории `research/market_structure_replay_20261104`:

```bash
python import_vision_zip.py --zip data/BTCUSDT-15m-2026-08.zip data/BTCUSDT-15m-2026-09.zip --out data/BTCUSDT_15m.csv
python replay.py --csv data/BTCUSDT_15m.csv --out results/BTC
python replay.py --csv data/BTCUSDT_15m.csv --out results/BTC_posthoc --allow-future-diagnostics
python compare_annotations.py --events results/BTC/events.jsonl --labels annotations/blind_reference.csv --out results/BTC/concordance.json
python -m unittest discover -s . -p 'test*.py' -v
```

Для 19 пар: по одному нормализованному CSV на монету и затем `python replay.py --csv data/*_15m.csv --out results/all19`. *Конвертация не скачивает ZIP автоматически.* Если конкретная монета ещё не была листингована в проверяемом периоде, исключить её **по дате листинга**, а не из-за плохих будущих результатов. Не заполнять пропуски синтетическими свечами.

## До независимой экспертной разметки

Аннотации: `symbol,event,known_at`, одна строка на человеческую метку. Разметчик должен видеть **только историю до текущего времени** и не видеть будущий исход, а также заранее зафиксировать правила выбора значимых структурных High/Low. Иначе согласованность измеряет ретроспективные догадки. Отдельно сравнить BOS/CHoCH из основной `ember.core.features` и признать расхождения открытым исследовательским вопросом, не автоматически считать ошибкой эксперта.

## Замороженный эксперимент / границы применимости

`Settings` фиксирует исследовательские параметры, прежде чем размечать будущие результаты. Временные масштабы: 1H накопление (12 свечей, ширина <=5 ATR(1H), дрейф <=40%); M (вынос 0.1–1.25 ATR(1H) и возврат); 15m swing 2+2; BOS >=0.15 ATR(1H); FVG >=0.15 ATR(1H). Это **гипотеза**, а не эталонная AMD. Настоящий анализ качества невозможен без независимой экспертной контрольной выборки и ошибок двух типов (ложно найденные и пропущенные).

**Ограничения:** нет тиковой последовательности, объёмных кластеров/CVD/order flow, достоверного намерения участников, BI/OB жизненного цикла, экспертной разметки, финансирования/funding, ордеров или финансовых выводов. Данные с futures-происхождением проверяются по пути, имени и SHA только при наличии внешнего источника, загруженного пользователем; `--allow-unverified` отключает даже проверку CHECKSUM и прямо помечает данные как UNVERIFIED. Один файл = одна непрерывная серия 15m. Для работы с архивами на постоянной основе надо дополнительно проверить provenance против независимых источников и расширить тесты CPU/memory для многолетних данных.

### Методическая защита

Нельзя смотреть на будущие исходы, чтобы «исправить» разметку в holdout; нельзя сравнивать доходность до доказательства корректного распознавания. CI PASS — только корректность проверяемых вычислений, не прибыль. `CONFIG` и `SOURCE_SHA` фиксируются в машинном аудите. Исходные предыдущие отрицательные тесты AMD остаются отрицательными для своих реализаций, а не переименовываются в положительные.
