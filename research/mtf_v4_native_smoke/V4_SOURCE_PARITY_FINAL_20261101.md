## Root cause: three subtle original-source selection semantics

1. **Source snapshots start with generation windows:** last 24 *structure events*, last 20 *confirmed pivots* and last 180 *4H source bars* for FVG. V3 had approximated OB expiry via last 24 unique OB births, which is different when more than one structure event references the same OB origin.
2. **Native dedup is performed before checking activity, with priority OB → swing → FVG.** V3 originally selected active candidates too early, admitting levels excluded by native `buildZones`.
3. **Critical subtlety:** the JavaScript original uses `Array.filter((zone,index,all) => all.findIndex(...) === index)`. This compares with *all previous source candidates*, **including previous candidates themselves suppressed** as duplicates. An intuitive greedy dedup against already-retained candidates is not equivalent when midpoint proximity is non-transitive: A ~ B, B ~ C, A !~ C. Exactly **six** additional previously unseen 250-snapshot mismatches exposed this error and were repaired with a unit regression.

Activity is determined by closes after the **origin** candle, not merely since late pivot confirmation; this too is preserved by the isolated Python source-selection port.
