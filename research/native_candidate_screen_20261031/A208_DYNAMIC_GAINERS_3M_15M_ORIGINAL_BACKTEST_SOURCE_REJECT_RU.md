# A208 — source-audit до бэктеста готового «топ-гейнер» 3m/15m скальпера: отклонён из-за исполнения и утечки будущей свечи

Дата 2026-10-31. Режим RESEARCH, NO ORDERS. Публичный источник `kiattisakph/crypto-scalp-bot@0ed020964abecedb6c587a7bdb2897b1ae360991`.

Идея на первый взгляд близка: dynamical top5/top10 USDT-M by change24h, 3m entry +15m confirmation, EMA9/21, RSI, volume1.5, ATR 0.8/1.5/2.5 TP, SL1×ATR, max hold30m, configurable 5×, three TPs, user paper trading. ## Подтверждённые исходником критические ошибки

**1. Доказанная lookahead утечка открывающейся свечи при сигнале и входе.**
- В `data_fetcher.py:223–238` `timestamp=datetime.utcfromtimestamp(k[0]/1000)` соответствует **open_time** биржевой свечи, хотя в этом же словаре уже лежат её итоговые `high, low, close, volume`.
- `backtest_engine.py:637,680–688` в момент `ts` получает и оценивает `sub_3m = df[timestamp<=ts]`, в том числе свечу, которая *только открылась в ts*, а её финальный close из будущего. То же для `sub_15m` и watchlist `_refresh_watchlist:801–810`. 
- `backtest_engine.py:711–745` производит вход по `entry_price=float(last_candle["close"])` **в тот же ts**. Реальная последняя свеча 3m на момент ts может быть известна только в ts+3мин; 15m — в ts+15мин. Внешний тестер получает цену не из будущей модели, а буквально из ещё не закрытой свечи. Это доказанное нарушение хронологии, не опциональная поправка комиссии.

**2. Ошибка времени выполнения при обычном закрытии.**
- `backtest_engine.py:892–934` функция `_close_position` в строке 911 записывает `pnl_pct=pnl_pct`, в строке930 выводит `pct=pnl_pct`, при этом ни аргумента `pnl_pct`, ни локального присваивания в её теле нет. Единственное присваивание `pnl_pct =...` присутствует в другой функции `_force_close_at:947` и недоступно `_close_position` (Python локальная область видимости). Первое естественное полное закрытие в таком оригинале даёт `NameError: name 'pnl_pct' is not defined`.
- В опубликованном README текстовый PnL пример `$10000->$12345.67` описан как `Console Report Example`, а не как actual SHA/ledger. Не цитировать его как подтверждённую доходность.

**3. Отсутствие комиссий и проскальзывания в движке.**
- `backtest_engine.py:307–310` `_calc_pnl` возвращает только `(exit_price-entry_price)*quantity` или зеркально short; **не вычитает fee, slippage, spread, не учитывает funding**. 
- `_close_position:899–920` добавляет к балансу `pos.realized_pnl_usdt` без fee/funding. В исходном базовом backtest нет полноценной экономической модели.
- Прогноз 3–5 сделок/сутки при сетапах на 3m в таком тесте не может быть принят без независимого движка, который использует следующий реальный open и 1m/3m stop-first.

**4. Универсальный 15m топ-гейнер скан сам по себе не гарантирует причинное исполнение.**
- `identify_qualifying_symbols` заранее собирает *все* монеты, которые когда-либо попадут в топ на всем тесте. Это само по себе допустимо лишь как приём предзагрузки свечей для полного universe, но не как фильтр реально известного в прошлом листинга. В `_refresh_watchlist` обнаружен основной дефект будущих close/volume на открытых 15m свечах (п.1).

## Результат source preflight
**A208 = BLOCKED/REJECT для оригинального «готового» бэктестера без финансового теста**. Не смешивать с A207 (тот действительно прошёл 120 real Binance source ZIP, 24 торговых журнала; A207 экономически FAIL). Нельзя делать вид, что текущий гейнер показывает доказанную прибыль. Можно исследовать после восстановления причинной временной шкалы, восстановления PnL и fee/funding, но такая версия **будет другой, адаптированной системой, не результатом оригинала** и требует отдельного pre-registration.

## Что полезно сохранить
- Предварительный выбор liquid 24h leaders и смена watchlist — гипотеза для отдельного теста с *point-in-time* universe.
- Схема `raw universe -> confirmed 15m context -> 3m event -> 30m time-stop` совместима с целью пользователя лишь как дизайн. Нужно проверять на реальных high/low, адаптивном MTF без lookahead.
- Обязательный аудит `timestamp=open` vs `timestamp=close` для ВСЕХ новых готовых терминалов; такие ошибки способны сделать любую стратегию бумажно прибыльной.
- Ручное исправление `pnl_pct` и добавление комиссий не разрешает повторно оптимизировать параметры на уже изученных 2024/2025/2026 годах.

Исходная идея не принесла проверенного дохода. При необходимости A209 следует искать другого **принципиально независимого** автора/класс с точным неизменённым signal+execution engine, не «переделывать гейнер» как оригинал.
