# MTF Course Fidelity v0.5 — начало исправления реализации, не новая прибыльная стратегия

Дата: 14.10.2026. **PAPER / EDUCATIONAL ONLY.** Этот пакет не заменяет основное ядро v0.3/v0.4 и не исполняет сделки. Создан, потому что тесты старой реализации не гарантировали соответствие исходной учебке. Тяжёлый исторический бэктест **не запускался**.

## Что реально исправлено в отдельном исходном модуле

- **3/5m BOS после 1H liquidity raid (ветка C):** 1H подтверждённый свежий pivot → рейд только фитилём с закрытием обратно → после закрытия часа 3/5m BOS по структурному уровню → **план не раньше открытия следующего младшего бара**. Нет подмены 15m SNR сигналом BOS.
- **Стоп после рейда и FTA:** проверяется естественная граница за экстремумом рейда, заранее известная 1H FTA, издержки обеих сторон; если цель невыгодна — reject. Не заявлять, что opening-price OHLC моделирует реальный fill.
- **Подтверждённые swing:** фиксация pivots только после двух правых закрытых свечей. Отрицательные и префиксные тесты исключают использование будущих данных.
- **IDM (ветка B):** 1H фрактал внутри или *перед* 4H POI, 15m внутри или перед 1H POI; не надо ждать финального BOS. Охранное StrongHL должно быть подтверждено заранее; поиск ещё не формирует ордер или FTA.
- **Strong High/Low:** swing сам по себе не становится strong. Требуются взаимодействие с ликвидностью/POI и более позднее VC/BOS, с хронологией подтверждения.
- **POI:** только первое касание ПОСЛЕ момента, когда зона стала известна; последующие тесты не «свежие».
- **5m IMB-кандидат:** трёхсвечный разрыв теней 5m, сигнал только после закрытия третьей свечи и полного формирования *после* 15m триггера. 15m данные недопустимо выдавать за 5m.

Технические синтетические тесты: **29/29 PASS**, Python stdlib, ~0.003 сек. Команда: `python -m unittest discover -s tests -v` из директории этого пакета. Отдельно проверено, что V0.4 **не менялась**.

## Чего в этой версии ещё НЕТ (важно)

- Нет автоматического полного связывания Daily POI → 4H raid/POI → 1H VC → 15m/5m маршрут A, потому что ещё нет заверенной разметки примеров.
- Нет доказанного «StrongHL из всех свечей»: есть требовательный к доказательствам контракт, а не картинка/автоматическая разметка всех ситуаций.
- Нет полной IDM-ордер-модели с FTA, и нет полной SNR/OB/RB-графической валидации против автора курса.
- В исходнике C торговые часы Frankfurt/NY указаны без подтверждённой IANA time-zone. Поэтому время сессии и строгая «предыдущая сессия» здесь не приписаны курсу. **24 часа freshness — открыто обозначенная аппроксимация** (по умолчанию параметр) и не доказательство того, что автор использует ровно 24 часа. Длительность до BOS по умолчанию не выдумана; `max_wait_ms` — исследовательский фильтр, если задан вручную.
- `confirmed_imb` — геометрия трёх свечей, без проверки цвета средней свечи: в доступном тексте однозначно сказано только, что цвет *первой и третьей* не имеет значения. Этот нюанс требует сверки оригинального изображения.
- Скриншотов с подтверждёнными границами POI, StrongHL, IDM, FTA пока **0**. Нельзя заявлять «учебная методика теперь реализована полностью».
- Ни одного полного торгового бэктеста в v0.5, PF/Win Rate/прибыльность **НЕ ИЗВЕСТНЫ**. Отрицательные результаты frozen v0.4 остаются достоверными **только для той реализации**.

## Контрольное направление продолжения

1. Достать авторские картинки 30–50 учебных случаев с ценой/временем и отдельно *отрицательные* случаи; сопоставить уровни и known_at.
2. Разметить ветви A/B и StrongHL с полноценной последовательностью parent POI/test→child, затем подтянуть исходный 3m/5m stream. До этой точки **никаких больших PF бэктестов**.
3. Только после parity-контроля отдельных паттернов запускать независимую историю Futures с предобъявленным протоколом и настоящими ограничениями исполнения.
