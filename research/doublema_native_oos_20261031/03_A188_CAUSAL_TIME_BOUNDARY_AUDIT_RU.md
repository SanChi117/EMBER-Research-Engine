# A188 — критическая проверка временной доступности Double MA, 31.10.2026

## Данные-основания
* Исходный upstream SHA: `40af5c7c1c44253766428cfb06babf22f9817aa4`, git blob `22ca6588bbd056e671783f676f1a4010cbfc1bb6`, класс `VideoDoubleMaFuturesStrategy`.
* Исходный Freqtrade `2026.4`; ранее в A187 получены 27 сделок (5 bps/side), прибыль +39.864%, PF2.239, DD7.332%; эти показатели **только воспроизводимы, не доказана причинная корректность**.
* Конкретный дефект: `_candles_until` делает `date <= current_time` (строки 460–467 исходника), `_entry_candle` выбирает последнюю с `date <= trade.open_date_utc` (446–457). В backtesting Freqtrade 2026.4 (`freqtrade/optimize/backtesting.py` рядом с 1621–1632) `_set_dataframe_max_index` вызывается после инкремента row_index, включая **текущую** свечу в `get_analyzed_dataframe`. Та свеча содержит high/low/close уже завершившегося в историческом наборе часа, которых при входе в час ещё не было. В реальном dry/live незакрытая свеча в analyzed dataframe отсутствует.
* Следствие: динамические стоп, RR/structure target, фильтр отмены, следящий выход и PnL могли опираться на недоступную при решении информацию. Это источник искажения исходного A187. Направление и размер искажения пока НЕ установлены.

## Регламент исправления
В **изолированной тестовой копии** автора, без изменения исходника и остальных параметров, одна строка:
```diff
- return dataframe.loc[dates <= candle_time]
+ return dataframe.loc[dates < candle_time.floor("h")]
```
Таким образом callbacks всегда получают только завершённые свечи **до начала текущей часовой свечи** (при 1h основной стратегии), и обрабатывают сохранённую свечу сигнала в момент входа. Параметры стратегии, маржа, риск и source OHLCV остаются неизменными.
