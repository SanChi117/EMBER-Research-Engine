## 3. Ошибка выявлена настоящим original source replay и исправлена

Первый CI [40192114201](https://github.com/SanChi117/EMBER-Research-Engine/actions/runs/40192114201) FAIL обнаружил неправильное предположение, что original3m ZIP SHA префикс **должен быть одинаков у соседних 3m баров**. Фактически в C46/C47 45 исходных ZIP исходные `sha256:bar_start_ms` идентификаторы меняются при переходе между соседними исходными **архивными сегментами**, иногда **внутри** октября 2026 (и при переходе September→October). Уникальный raw-source ID остаётся корректным; главное — **точная причинная связка с проверенными исходными C46/C47 и исходными файлами**, а не «все данные из одного ZIP». Отказ от ошибочного SHA-равенства НЕ означает, что произвольный source ID принимается как факт: exact ID/touch/4H ID/1H ID независимо перекрёстно сверяются в source probe с **двумя ранее принятыми оригинальными C46+C47 JSON**, а те воспроизводятся из полных 45 original ZIP.

Один тест первоначально был настроен на ложное ожидание отказа при корректном сменившемся ZIP SHA. Тест исправлен: правильная разная SHA по соседним источникам допускается, но не повышает ни одну source-зону до академического POI/VC. Другие 48 отрицательных проверок продолжают защищать интервалы времени, формат raw-ID, исходный инструмент, невозможный будущий source и подмену курсного режима. Исправление проверено **49/49 × Python 3.10/3.11/3.12**.
