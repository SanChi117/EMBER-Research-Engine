Из текста следует: **Volume Confirmation не тождественен величине биржевого поля свечи volume**. Подтверждение описано как образование POI (IMB/SNR/RB) либо BOS после цены, контактирующей с ликвидностью/неэффективностью. Для **непосредственного входа по VC** методика ограничивает проверяемые источники **SNR или IMB**; RB может подтверждать 1H движение и быть новой 1H POI, но это не делает 5M RB разрешённой entry VC.

### Проверяемые ветви

1. 4H POI **TEST** → есть 1H Trigger (BSL/SSL или IMB при применимом SNR/RB) → 15M VC (IMB/SNR).
2. 4H POI TEST → нет 1H Trigger → подтверждённая 1H VC (IMB/SNR/RB), которая становится **новой POI** → позже её 1H TEST → нет 15M Trigger → 15M VC (IMB/SNR).
3. Та же созданная+протестированная 1H POI → присутствует 15M Trigger → **5M** VC (IMB/SNR).
4. 4H **Liquidity Raid** → трактуется курсом как отсутствие 1H Trigger, поэтому сначала 1H VC/новая POI/тест, затем без 15M Trigger 15M VC или с 15M Trigger 5M VC.
5. **IDM — не отдельный контекст**, но иной способ исполнения: при заранее подтверждённой старшей VC, StrongHL и допустимой liquidity IDM новый завершающий 15M/5M VC не обязателен. Реальную заявку этот цикл не создаёт.
6. Текст отдельно уточняет: «4H IMB → внутри не рассматриваем 1H IMB» именно **как LTF Trigger**, а не запрет 1H VC IMB после реакции на 4H IMB (прямой пример 4H IMB → 1H VC IMB в том же источнике). Для 15M IMB Trigger требуется опорная SNR/RB, не произвольная IMB. Автоматически подтасовать 15M в качестве 5M нельзя.
7. Таргетирование по исходному 4H уровню должно использовать **4H FTA**; точный уровень/защита SL ещё не размечены на свечах.
