# EMBER C81 — очередь независимой проверки исходных crypto-контекстов

Дата: 2026-10-26. Принятая точка входа C80/A150 (150/150 SHA).
Режим: **PAPER ONLY / NOT_TRADE_READY**.

## Результат

Сформирована реальная **source-only очередь 153 контекстов** из
криптографически закреплённых C73 и C72 (оригинальные Binance USD-M
BCH/BTC/ETH/SOL/XRP, 3m/5m/15m/1h/4h источники прежних этапов).
Файл `evidence/c81/C81_FROZEN153_INDEPENDENT_REVIEW_QUEUE_SOURCE_ONLY.json`
содержит полные 153 source пакета, точные индексы, стороны, время создания POI,
первый сырой 3m ID, 15m/5m времена, число отдельных посещений, C67
ветку, приоритет, пустые авторские поля и `NOT_TRADE_READY`.
Это **НЕ 153 сигнала** и **НЕ набор авторских goldens**.

Порядок очереди детерминирован: (приоритет, symbol, original4h-parent-index).

| Категория | Количество | Разрешённая интерпретация |
|---|---:|---|
| P0: выбранная 1H ветка + 15m и последующий 5m source | 12 | Первоочередные кандидаты на ручную сверку правил, **не входы** |
| P1: выбранная 1H ветка + raw3m touch, нет однозначного 15m | 23 | Физический touch, **не авторский first valid test** |
| P2: C67 opposite/ambiguous, 1H не выбран | 71 | Отрицательные контрпримеры для развилки, **не авторски размеченные negatives** |
| P3: без новой 1H POI | 47 | Контрольная группа без новой POI; в **23 из этих 47** есть сырой 3m touch другого контекста, который нельзя считать новым 1H POI test |

Двенадцать первых ключей для проверки:
`BCHUSDT/3, BCHUSDT/6, BCHUSDT/7, BCHUSDT/16, BCHUSDT/21,
BCHUSDT/30, BTCUSDT/2, BTCUSDT/7, BTCUSDT/24, ETHUSDT/8,
SOLUSDT/1, XRPUSDT/20`.

## Реальные проверки и опровержение

`d05/c81_source_authenticated_review_queue.py` загружает **только**
оригинальные байты C73/C72 с pinned SHA/BLOB; отбрасывает чужую
маршрутизацию, future 5m before 15m, несоответствие C67,
поддельные статусы, неправильные count/priority и мнимые сделки.

`tests/probe_c81_independent_153_queue.py` **независимо** пересоздаёт
все 153 пакета и сравнивает **каждое поле и сериализованные байты**
с frozen JSON. Проверенный файл: **148772 байта**, SHA256
`07d3fe70a4af5cdc6878b6645025606c0ff4549e70e5eb8305ef685544170df6`.
C73 SHA `c79892079f00952030b778985b53c2cc11bd2e05bf1ea70555d4385bd7963f6b`,
C72 git blob `19b7e0357600b70b3f26467339a417e0f99a1302`.

**Реальный CI** [GitHub Actions #40387188743](https://github.com/SanChi117/EMBER-Research-Engine/actions/runs/40387188743):
**43/43 тестов Python 3.10, 3.11, 3.12 — SUCCESS**, все 153
пакета byte-for-byte PASS. Первые два прогона C81 были красными:
они выявили (а) 23 source-touch без новой 1H POI и (б)
несовпадение Python tuple vs JSON list до сериализации. Исправлено без
изменения старых C73/C72 данных; последний CI green.
Эти неудачи сохранены в Actions, а не скрыты.

## Необходимая настоящая академическая разметка

Для каждого реального POI first-test/15m Trigger/15m direct VC/5m VC/
StrongHL нужны авторский исходник с точным кадром/страницей, оригинальный
symbol + TF + closed timestamp + OHLCV, независимый proof of source,
**положительные И отрицательные случаи**, а затем независимое воспроизведение.
Кандидат, которому приписаны arbitrary URL/hash/reviewer, помещается в
`QUARANTINED_EXTERNAL_OWNER_MEDIA_UNAUTHENTICATED`, даже если выглядит
правдоподобно. Он НИКОГДА не становится `AUTHOR_VERIFIED` или entry.

Оригинальные ZIP в C81 заново не скачивались; C73/C72 frozen
source-архивы использованы по контрольным SHA. Нет goldens, сделок,
ордеров, fills, PnL, SL/FTA/TP. Routes B/C и V5/QFVG не изменены.

Следующий цикл C82 — проверяемый ручной протокол независимого label-review
(отдельный author vs ADAPTED_HYPOTHESIS) и реплей original crypto
PAPER OOS исключительно в качестве геометрической проверки, без
фиктивных «авторских» входов и прибыльности.
