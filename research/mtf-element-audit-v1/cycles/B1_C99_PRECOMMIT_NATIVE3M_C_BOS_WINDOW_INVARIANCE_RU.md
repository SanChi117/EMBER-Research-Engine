# C99 — до расчёта результатов: независимая проверка устойчивости 3m BOS к началу истории

Задача: возможная проблема C98 — Route C берёт строго 32 дня исходной истории, но построение 1H FTA не имеет такого же конечного лимита возраста, поэтому сигналы на тех же октябрьских свечах могут зависеть от выбранного начала 32-дневного окна. Нельзя лечить это настройкой RR и нельзя объявлять C стабильным без проверки.

**До расчёта результата** зафиксированы:
- источник: *те же* original Binance native3m ZIP Sep1–Oct26, с ранее проверенными C21 Sept1–Oct2 и **120 Oct03–Oct26 native3m** ZIP, SHA каждого из C98 frozen witness; никаких 5m→3m прокси;
- сам торговый код: неизменённый `c93_native3m_raid_bos_route_c_research.discover()`;
- три независимых окна **ровно по 32 полных суток**, завершённых `2026-10-10T00:00Z`, `2026-10-18T00:00Z`, `2026-10-27T00:00Z`;
- сравнение одних и тех же исходных решений C между каждым сочетанием двух окон на общей истории от `max(start windows)+7 полных суток` и не раньше **Oct03** до `min(end windows)-12h` (на вход, SL, TP, FTA, R и выход). 7 дней — исследовательский контекстный минимум, не параметр прибыли;
- если одно и то же закрытое решение меняется от окна, фиксировать **CONTEXT_UNSTABLE** и различия, а не улучшать входы. При нуле общих подтверждённых сделок фиксировать **NO_POWER** — не объявлять успешную устойчивость;
- не загружать новые монеты, не изменять старые сделки и критерии, не использовать деньги / реальные ордера.

Сформировать JSON свидетельство 3 пар окон × 5 символов, negative tests на подмену префикса и сдвиг, GitHub CI, SHA-журнал и отчёт по фактическому исходу.

Если C99 находит нестабильность, исправление будет отдельным новым циклом с новой неподсмотренной выборкой. Если нет — это подтверждает только ограниченный сравнительный отрезок, а не положительное математическое ожидание.
