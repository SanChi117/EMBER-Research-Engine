# C101 — зарегистрированный до написания анализатора протокол: 48 исторических C98 исходов на оригинальных native3m / native5m
Дата: 2026-10-29. **PAPER ONLY, POST_HOC_DIAGNOSTIC, НЕ OOS, НЕ ОПТИМИЗАЦИЯ СТРАТЕГИИ.**

## Цель
Проверить по исходным свечам Binance Vision фактические временные и ценовые предпосылки уже известных исторических C98 сделок: 7 A / 3 B / 38 C. Сверить 14bps netR и типы выхода по исходному rulebook C91/C94/C93. Отделить доказанный технический дефект от предположений о ложном рейде / слабом BOS / неверном POI. Результаты не разрешают реальных ордеров.

## Источники и защитные правила
1. Единственный каталог действительных SHA256 — **замороженный** `evidence/c98/C98_NEW_OCT_SOURCE_ABC_CLOSED_HOLDOUT.json` SHA256 `9b95735407465c46b1a2fdb6e4e8875bfdd2c428588f6205bf1212d35c0b9e97`. В нём 240 исходных ZIP с ZIP/CSV SHA и 48 сделок. Не перекладывать источниковые свечи на другой ТФ. A/B — 5m, C — 3m. Прочесть original `C93`, `C94`, `C91` до реализации replay.
2. Для каждой сделки из известных 24 дней 03–26 октября запросить лишь требуемые ежедневные native ZIP Binance Vision, достаточные для хронологического replay вход→выход, а также один день до входа если он содержится в C98. Подписанный SHA каждого заново полученного ZIP и CSV обязан совпасть с исходным manifest; не загружать из другого хоста. `.CHECKSUM` same-host — НЕ сторонняя подпись.
3. Проверять СТРОГО: Entry A/C = OPEN исходной первой свечи; B entry=limit и бар реально коснулся лимита (при первом касании B TP не зачитывать); каждую следующую свечу до exit; gaps, SL/TP с **консервативным STOP-FIRST** при dual touch; exit bar close-ms, reason и netR по 14bps. Если неоднозначность, отдельно поставить `BOTH_SL_TP_IN_SAME_BAR`; не притворяться, будто OHLC раскрывает истинную последовательность тиков.
4. Признаки `as-of entry`: только полностью закрытые свечи; медиана предвходного истинного диапазона на последних 20 native барах; расстояние SL в единицах этой медианы; `B` возраст IDM→сигнал→исполнение; `A` POI/FTA/VC время; `C` raid fractal known, полный 1h raid wick/reclaim по 20 native3m, BOS закрытие 3m относительно заранее известного уровня, отношение тела BOS к его диапазону. НЕ использовать исход торговли для формирования pre-entry признаков. Не использовать 5m вместо 3m.
5. Индивидуальная карточка исследования: символ, route, UTC timestamps, SHA(архивы) реального источника, 14bps netR и exit reason (обязательно точное совпадение), возможный dual touch, MFE/MAE по OHLC после входа (post-exit не смотреть), as-of признаки с временным тегом, явная пометка `POST_HOC_HYPOTHESIS`.
6. Выход: frozen `evidence/c101/C101_C98_SHA_PINNED_NATIVE_BAR_CAUSAL_FORENSIC.json`, компактный общий отчёт, негативные тесты, SHA append-only A165 и независимый CI. Никаких фильтров на выборе winning trades, изменения fixed RR и модификаций A/B/C; сохраняя все прежние исходы и source hash.

## Предзаданные критерии приемки
- **48/48** сделок должны replay соответствовать всей последовательности закрытых баров, reason и 14bps net R с абсолютной погрешностью <=0.000001; ни одна не пропущена.
- **0** неподписанных/несовпадающих ZIP/CSV, **0** неправильных 3m/5m подмен, **0** future-as-of при построении сигналов.
- 25+ отдельных негативных тестов, полный предыдущий регрессионный набор 512 тестов на Python 3.10/3.11/3.12; независимый CI только после сохранения witness.
- Если оригинальные ежедневные свечи недоступны/источник не проходит SHA, отметить `BLOCKED` и НЕ выдавать полный успешный цикл, не выдумывать выводы.
- Экономический приёмочный порог (будущий C102+): ранее зафиксированный >=30 независимых OOS сделок/маршрут, >=10 на временной блок, netR25>0, PF25>1.2, PF40>1.1, illustrative DD<10%. C101 — только already-seen sample и **не участвует в новом OOS**.

## Исследовательские гипотезы, строго не утверждения
H1: доля модельных 14→25bps издержек от структурного 1R растёт при малой дистанции Entry→SL. H2: native3m BOS ratio и 1H Raid wick/reclaim отличаются в stop и FTA исходах. H3: время ожидания B лимита, преждевременная инвалидация и first-touch влияют на исполнение. H4: старение POI/FTA и задержка VC влияют на A. Каждая идея **post-hoc**, без перепроверки на новом неизученном источнике нет доказательства.
