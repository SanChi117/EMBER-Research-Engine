# Протокол MTF: запись → опровержение → решение

**Версия PROTOCOL-1.0, дата 2026-10-14.** Применяется ко всем будущим самостоятельным задачам по MTF. Существующие стратегии, терминал и LIVE-системы этот документ не изменяет.

## 1. Что считается выполненным

- Каждое действие получает неизменяемый `action_id`, номер шага, имя цикла, план, реально сделанное, наблюдаемый результат, SHA256 всех доказательств и контрпроверку.
- Для `DONE` обязателен **непустой файл доказательства**, подтверждённый хэшом. Комментарий или обещание не доказательство.
- Задача без действительной записи со статусом `DONE` считается **НЕ ВЫПОЛНЕННОЙ**.
- Сбой фиксируется как `FAILED` с traceback/артефактом. Ошибочную предыдущую запись нельзя удалять/переписывать: последующее действие **инвалидирует** её ID.
- Журнал JSONL использует сквозную SHA256-цепочку. Она защищает от случайного незаметного изменения, **не от администратора, переписывающего всю историю**. Для внешнего якоря нужна фиксация в Git.

## 2. Контрольные циклы

1. **Гипотеза**: одно чёткое утверждение (например, «каждая возвращаемая свеча уже закрылась к `as_of`»).
2. **Заранее указанная граница**: вход/выход, источник, допустимые исключения, статус.
3. **Доказательство**: исходный фрагмент, fixture/CSV, автоматический или ручной протокол проверки с SHA256.
4. **Попытка опровержения**: отрицательные кейсы, границы, фальсификация, альтернативная версия проблемы.
5. **Воспроизведение**: независимый повтор или другой источник; совпадение обязано быть фактическим.
6. **Решение**: `VERIFIED_FORMAL`, `VERIFIED_SEMANTIC`, `REJECTED`, `BLOCKED`, `NEEDS_LABEL`. Инженерный `VERIFIED_FORMAL` **не равен** семантической аттестации учебной формации.
7. **Открытые дефекты**: фиксируются даже если другие проверки прошли; новая работа только новым номером версии/цикла.

## 3. Жёсткие запреты

- Нельзя присваивать `DONE`, если нет результата или доказательства. Равные пустые файлы не означают «два успешных запуска».
- Нельзя принимать учебный IDM как pivot, StrongHL как min/max, BOS3m как SNR15m, FTA как любой ближайший экстремум без отдельного доказательства.
- Нельзя менять метку после просмотра PnL; бэктест **не подтверждает смысл** элемента.
- Нельзя переносить результат одной версии на другую или подменять Spot/Futures.
- Не изменять V2.2, v0.4/v0.5, терминал, боевые стратегии; отдельное исследование без заявок.

## 4. Статусы

| Статус | Что значит | Следующий шаг |
|---|---|---|
| `VERIFIED_FORMAL` | Синтаксис, даты/арифметика и зафиксированные тесты подтверждены | Проверить реальным источником, семантику отдельно |
| `VERIFIED_SEMANTIC` | Элемент совпал с независимо размеченными источниками и выдержал негативные примеры | Допустить к связям |
| `REJECTED` | Есть прямой воспроизводимый контрпример | Исправить в новой изолированной версии |
| `BLOCKED` | Нет нужного источника/разметки или запуск не состоялся | Сохранить недоказанность |
| `NEEDS_LABEL` | Есть текстовое описание, но нет качественных размеченных эталонов | Сформировать positive/negative label set |

Стабильность ≠ «правда навсегда». До независимого подтверждения отображается точный уровень доказанности, а не слово «готово».
