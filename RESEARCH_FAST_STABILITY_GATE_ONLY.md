## Обязательный порядок A224+

1. Поиск и дедупликация. Запрещено возвращать A188–A223 и veto A220 без новой сильной независимой гипотезы. Выбирай готовые полные оригиналы с исходным SHA и понятной экономической причинностью, а не «красивыми» README/сигналами.
2. **Сначала быстрый экономический smoke**, не многодневная экспертиза исходного кода. Для честной интерпретации, однако, перед расчётом проверь: реальный USD-M market venue, закрытые свечи/вход позже сигнала, отсутствие peek/lookahead и исполнимые стопы. Если source fails — короткий внутренний `BLOCKED`, без нового длинного отчёта.
3. Рабочий smoke-gate (исследовательский порог, не обещание прибыли):
   - frozen оригинальные сигналы и параметры без тюнинга;
   - authentic Binance USD-M raw/cached checksumed OHLCV и по мере применимости реальный funding, маржа/mark; если подлинные данные недоступны — `INSUFFICIENT`, не проход;
   - после комиссии и slippage положительная чистая экономика хотя бы в **двух разделённых рыночных годах/режимах**, без скрытого катастрофического третьего года, и не исчезающая в заранее фиксированном stress-cost;
   - max equity DD и худшая сделка сопоставимы с заранее заданным бюджетом риска, нет margin/liquidation cliff;
   - достаточное фактическое количество сделок для смысла результата, отдельные логи и источники, без компрометации заранее отложенного future/OOS. Если выборка мала, статус `INSUFFICIENT`.
4. **Только при прохождении smoke-gate** допустим долгий аудит, исследование robustness sweep без переоптимизации и независимое хронологическое OOS/forward PAPER. Smoke PASS сам по себе **НЕ делает стратегию VERIFIED**.
5. **Не присылай промежуточных разборов, идей, негативных скринов, README Sharpe и списков претендентов пользователю.** Отправляй короткое сообщение **только** когда результат smoke подтвердил устойчивость настолько, что кандидат заслуживает следующего полного теста. Указывай ровно сколько лет/сделок, after-cost net, worst DD, ограничения и ссылку на CI/реестр; прямо `PRELIMINARY`, пока нет forward.
6. Сохраняй технические следы в GitHub по существующему исследовательскому маршруту, не меняй действующие PAPER/автоматизации и не размещай реальные сделки.
